# AI forward-deployed engineer

**Make AI work inside a customer's actual workflow.** Often shortened to FDE, forward-deployed engineering combines hands-on implementation with discovering requirements, adapting integrations, and helping users adopt a system. The title is also used outside AI.

Some employers say *forward-deployed AI engineer*, *AI deployment engineer*, or *implementation engineer*. The amount of coding, consulting, travel, and sales support varies substantially. Read the responsibilities and interview expectations, not just the name.

## What the work looks like

A customer might ask for an “AI assistant,” while the underlying need is to reduce time spent moving information between systems. An FDE observes that process, identifies which steps can be improved, and builds a practical integration.

Typical work includes stakeholder interviews, prototyping, connecting APIs and data sources, adapting software to customer permissions, debugging deployment problems, and documenting the handoff. The engineer feeds recurring customer needs back to the product team so that one-off work can inform reusable features.

Success depends on both technical function and adoption. A demonstration can be impressive while still failing the customer's security review or day-to-day workflow. Good deliverables include an implemented integration, acceptance criteria, an evaluation report, training material, and an owner for ongoing operation.

## Skills to develop

- **Implementation:** Python or TypeScript, APIs, databases, authentication, and debugging across systems.
- **Discovery:** asking clear questions, mapping workflows, and separating symptoms from underlying needs.
- **AI judgment:** selecting suitable patterns, designing evaluations, and identifying where human review is necessary.
- **Communication:** explaining tradeoffs, managing scope, writing handoff notes, and working with technical and nontechnical partners.

Comfort with ambiguity helps, but it should lead to explicit assumptions and measurable acceptance criteria rather than promises the system cannot keep.

## Illustrative job brief

::: info Example written for this atlas
Work with a customer operations team to prototype an assistant for categorizing support requests. Connect the customer's ticketing API, preserve existing access permissions, test representative cases with users, and document rollback and escalation procedures. Share common integration requirements with the core product team.
:::

This brief describes a possible assignment. It is not a current vacancy or a claim about a particular employer.

## A realistic entry route

Build software for a real club, volunteer group, or small organization using public or approved non-sensitive data. Practice gathering requirements before coding and getting feedback after deployment. Internships in software engineering, implementation, solutions engineering, or technical consulting can build relevant experience.

Many FDE roles expect independent engineering judgment. For an early-career applicant, supervised implementation work can be a more realistic first step than owning an entire customer deployment.

## Portfolio proof

Create a mock customer case study: a workflow diagram, discovery questions, a small integration, a test plan, and a handoff guide. Clearly label simulated stakeholders and data. Explain what you changed after feedback and which tasks remain manual. Show code and tradeoffs as well as the final interface.

## How this role differs

An [AI engineer](/roles/ai-engineer) may focus on reusable product features. A [solutions architect](/roles/solutions-architect) often concentrates on system design and technical alignment. An FDE commonly takes a more direct implementation role within a particular customer context, though organizational boundaries vary.
